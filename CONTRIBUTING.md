# Contributing

This is a learning repository: small, understandable changes make work easy to review and recover.

## Commits

- Complete one task, then make one commit; do not mix unrelated tasks.
- Use a clear message with the task ID, for example `F-03 render hardcoded options`.
- Commit as you work, not only at the end.

## Pull requests

- Work on a branch.
- Title each pull request `TASK-ID: short description`, for example `B-02: add GET options route`.
- Say what now runs and how to check it.
- Never squash-merge: task commits are part of the learning record.

## Reviews

Review at least one teammate's pull request each week. Check that it runs, meets the task requirement, and that the author can explain their code. See [docs/team-roles.md](docs/team-roles.md).
